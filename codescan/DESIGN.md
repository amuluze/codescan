## 2. 产品面

| 产品面 | 实现位置 | 用户 | 设计目标 |
|---|---|---|---|
| 桌面应用 | `apps/desktop`（Tauri 2 + React 19 + Rust） | 开发者 / 安全与质量负责人 | 精确、可核对：结果可复现、证据可定位、门禁差异可解释 |
| 官方网站 | `../website/`（独立静态 HTML/CSS/JS，无构建步骤） | 访客 / 潜在用户 | 讲清「这是什么、怎么装、凭什么可信」；以 §3.1 母色为唯一品牌来源 |

本文后续章节默认描述桌面应用；官网拥有独立的实现与维护约定，仅共享品牌来源。

### 2.1 桌面应用的产品面性质

单窗口、本地优先、只读：扫描不写工作区，产物只落本地数据根（`~/.codescan/`）。这一性质决定全部视觉取舍——界面是「工作台」而不是「看板」：密度优先、状态可核对、动效克制。

### 2.2 基调

| 基调 | 含义 | 视觉表现 |
|---|---|---|
| 可信 | 深色、克制、不惊悚 | 深空蓝黑底、单一主色、无霓虹、无大面积渐变 |
| 精确 | 数据可核对、状态可区分 | 等宽字体、等宽数字、颜色 + 文字双编码 |
| 克制 | 动效服务于状态，不表演 | 过渡 ≤ 200ms；唯一常驻动效是扫描进度 |

反向清单：不用红底闪屏、不用拟物阴影、不用 emoji 充当功能图标、不用彩虹色编码维度、不在界面里堆装饰插画。

### 2.3 品牌位规则（跨产品面）

- 字标（`logo.svg`）只用于品牌位：README 首图、文档头图、网站顶栏；产品界面内（导航、页面标题、窗口标题栏）不重复绘制字标，避免与图标重复表达。
- 产品名统一写作 **CodeScan**；打包标题沿用 `apps/desktop/src-tauri/tauri.conf.json` 的 `Codescan`，不为对齐大小写而改动品牌写法。
- 官网如落地，只允许浅色底 + monochrome 字标（待补资产，见 §3.5 与 §11），不得直接用现 wordmark。

## 3. 品牌与色彩

### 3.1 品牌母色（唯一来源：`assets/brand/*.svg`）

`assets/brand/icon.svg`（viewBox 1024×1024）由四层构成：应用底板（800×800 圆角方块，rx=186 ≈ 边长 23%，深空蓝黑渐变）、顶部光泽（白色 10% → 0 斜向高光）、内描边（`#2b3d58`，8px）、扫描镜头 + 代码字形（镜圈 r=206 描边 64 + 手柄描边 88，镜中 `</>` 字形描边 62、色 `#edf4ff`）。

语义读法：**镜头 = 扫描**、**`</>` = 源码**、**字形被罩在镜中 = 对代码做扫描**。镜圈的蓝→青渐变表示光学感与「扫描进行中」，是品牌中唯一允许的渐变。

| 母色 | 值 | 出处 | 角色 |
|---|---|---|---|
| `tile-deep` | `#0a1019` | tile 渐变 offset=1 | 应用底色 |
| `tile-mid` | `#0e1624` | tile 渐变 offset=0.55 | 抬升层（导航） |
| `tile-top` | `#131e30` | tile 渐变 offset=0 | 表面层（卡片） |
| `mark-blue` | `#5b9cff` | mark 渐变 offset=0 | 主强调色 |
| `mark-cyan` | `#7ce6ff` | mark 渐变 offset=1 | 次强调色 |
| `glyph` | `#edf4ff` | `</>` 描边 | 主文字色 |
| `hairline` | `#2b3d58` | tile 内描边 | 分隔线 / 边框 |
| `wordmark-gray` | `#8b98a5` | 字标 `Code` | 次要文字色 |
| `sheen` | `#ffffff` 10% → 0 | tile 高光 | 仅用于品牌资产，不进 UI |

|---|---|---|

**命名规则**：族前缀 + 语义后缀（`--surface*`、`--fg*`、`--border*`、`--accent*`、`--error/warning/info`）。同一语义不得出现第二个 token（例：不得同时存在 `--muted` 与 `--text-secondary`）。

### 3.3 语义使用规则

1. **主色只做「可点」和「当前」**：主按钮、激活导航、当前 Tab、焦点环、进度条。不用主色做大面积背景。
2. **状态色三件套**：实心（文字/图标/描边）+ soft（标签底、图标底）+ 弱化文字（说明）。严重级三档必须成套出现。
3. **数字一律等宽**：计数、百分比、行列号、文件数、字节数、时间戳、版本号使用等宽字体并 `tabular-nums`。
4. **字号承载层级，不承载情绪**：层级靠字号与字重区分，不靠颜色深浅制造主次。
5. **字重分工**：600 = 标题、关键数字、主按钮文字、状态标签；500 = 次级强调（按钮、表格主字段）；400 = 正文与说明。
6. **弱化分隔符**：同一行内的元信息用 `·` 分隔，不用竖线或多个空格。
7. **等宽字体不用于中文文案**，只用于数据。
8. **颜色预算**：品牌色只标记「当前焦点」，单屏品牌色面积 ≤ 10%。
9. **`--accent-2`（青）不做正文色、不做大面积底**（高亮过曝），只用于：进度条渐变终点、hover 态、渐变终点、图形细节。
10. **维度不另配色**：安全 / 业务逻辑 / 质量用中性 chip + 文字，避免与严重级抢色、避免暗示严重性。
11. **规则消息与文案不着色**：只有 UI 元件着色，消息正文保持 `--fg`，便于长文本阅读。

| 组合 | 比值 | 判定 |
|---|---|---|
| `--fg-strong` / `--fg` on `--bg` | 17.9 / 17.2 | 通过（正文 ≥ 4.5） |
| `--muted` on `--bg` | 6.5 | 通过（次要文本 ≥ 4.5） |
| `--faint` on `--bg` | 3.8 | 仅禁用态/装饰，不承载正文 |
| `--accent` / `--accent-2` on `--bg` | 6.9 / 13.3 | 通过 |
| `--error` / `--warning` / `--info` on `--bg` | 6.8 / 10.2 / 8.8 | 通过 |
| 主按钮文字 `#05101f` on `--accent` | 7.0 | 通过 |
| hover 态文字 `#05101f` on `--accent-2` | 13.3 | 通过 |
| `--border-strong` on `--bg` | 3.5 | 通过（非文本 ≥ 3） |
| `--border` on `--bg` | 1.7 | 装饰性分隔线允许；不得用于可交互控件边界 |
| 字标灰 `#8b98a5` on 白底 | 2.8 | 浅色底禁用现 wordmark |

### 3.5 品牌资产使用规范

| 项 | 规则 |
|---|---|
| 最小尺寸 | icon ≥ 16px（16px 时仅底板 + 镜圈可辨，字形必然糊）；推荐 ≥ 20px。logo 最小宽度 96px（字标约 30px 高）。 |
| 留白 | 四周留白 ≥ 图标边长的 12%（icon 稿内已有约 11% 内缩，外部不再叠加）。 |
| 禁止 | 改变宽高比、旋转、给 icon 去掉底板、给字标换色、给 logo 加描边/背景、改变渐变角度。 |
| 深色背景 | icon 自带底板，可直接放置；需要贴合深色 UI 时可加 `0 18px 36px rgba(0,0,0,.35)` 柔和投影，**不得加发光**。 |
| 浅色背景 | logo 中 `Code` 的 `#8b98a5` 在白底对比度仅 2.76:1，**浅色底不得使用当前 wordmark**；需先产出 monochrome 变体（单色 `#131e30`）——仓库暂无该资产，属待补项（§11）。 |
| 打包图标 | `apps/desktop/src-tauri/icons/*` 必须由 `icon.svg` 栅格化，保持圆角比例与配色一致，不允许用第三方图标替换。 |

## 4. 页面地图

桌面应用为**单窗口 + 顶部标签导航**结构（`App.tsx`），五个视图互斥渲染，不做路由跳转。

| 视图 | 组件 | 页面结构 | 覆盖的界面 |
|---|---|---|---|
| 扫描 | `ScanView` | 标题区 → 工作区路径行 → 扫描卡（状态 + 进度 + 统计网格）→ 扫描结果卡 → LLM 源码审查卡（参考） | 选择工作区、启动/取消扫描、进度与统计、LLM 审查入口 |
| 发现 | `FindingsView` | 标题区 → 工具栏（筛选 / 搜索 / 计数）→ 汇总条 → 左列表 ↔ 右详情 → 批量分诊卡（参考） | 发现浏览、筛选、证据与污点链详情、LLM 分诊 |
| 规则 | `RulesView` | 加载态文案 → 自定义规则加载错误 → 规则表（启用 / id / 语言 / 维度 / 严重级 / 说明） | 内置与自定义规则目录、启停、编译错误展示 |
| 历史 | `HistoryView` | 扫描记录表（查看 / 设为基线 / 门禁差异 / 导出 SARIF / 删除）→ 门禁差异区 → 选中扫描的发现详情 | 扫描回溯、基线设置、门禁差异、SARIF 导出、删除 |
| 设置 | `SettingsView` | 标题区 → 模型 Provider 卡 → 应用更新卡 → 安全边界说明卡 | LLM Provider 配置（密钥只显示状态）、更新检查、安全边界说明 |

**弹层**（应用内实现，不使用系统原生对话框）

| 弹层 | 组件 | 结构 | 约束 |
|---|---|---|---|
| 目录选择器 | `DirectoryPicker` | 头部（标题 + 关闭）→ 路径输入 → 上级 / 子目录列表 → 底部（当前路径 + 取消 / 选择此目录） | `role="dialog"` + `aria-modal="true"` + `aria-label`；列表空态「此目录没有可进入的子目录」，读取中「读取目录…」，读取失败 `role="alert"` |

### 4.1 全应用状态与边界态

| 态 | 落点 | 表达 |
|---|---|---|
| 扫描中 | 扫描页 | 进度条 + 百分比（tabular-nums）+ 可取消 |
| 扫描完成 | 扫描页 | `--info` 状态文字 + 统计网格 |
| 扫描取消 | 扫描页 | `--muted` 状态文字（与失败明确区分） |
| 扫描失败 | 扫描页 | `--error` 文字 + 可读原因 |
| 加载中 | 规则页 / 历史页 | 「加载规则…」等中性文案，保留布局尺寸不跳动 |
| 空态 | 各页 | 标题 + 一句因果说明 + 可执行入口（不插画、不用感叹号） |
| 错误 | 规则页 / LLM 区块 | `role="alert"` 的可读错误文案，不弹窗、不闪烁 |
| 降级 | 发现页 / 历史页 | `degraded` 标记（`--warning`），表示容错解析产生的发现 |
| 参考层 | 扫描页 / 发现页 | `.discipline-tag`「非确定性参考 · 不参与门禁」，LLM 产出与发现物理分区 |
| 二次确认 | 历史页删除 | 内联「确认删除 / 取消」两按钮，不用原生 `confirm` |
| 弹层 | 扫描页（目录选择器） | 遮罩 + 居中 Modal；头部与底部各有退出入口 |
| 复制反馈 | 证据块 / 分诊区块 / 规则 YAML | 按钮文案三态「复制 → 已复制 / 复制失败」，1.6s 回落，不弹 toast |

### 4.2 空态文案口径

空态固定三段式：**发生了什么 → 为什么 → 怎么做**。

- 发现页：「无匹配发现」+ 二选一说明——无扫描记录时「先在「扫描」页选择工作区并运行一次扫描。」；有扫描但过滤后为空时「当前过滤条件下没有结果，尝试放宽维度 / 严重级或清空搜索。」
- 扫描页（LLM 审查空态）：「未发现问题（参考）；这不代表代码安全。」
- 历史页：「暂无扫描记录」+ 引导去扫描页。
- 规则页：不设空态（规则集随引擎版本内置，始终有内容）；加载失败才是错误态。

## 5. 布局系统

### 5.1 应用骨架

所有视图共用同一骨架：**顶部导航 → 内容区**。无底部状态栏（桌面应用不需要常驻运行信息；运行时长等属于扫描会话的临时态，落在扫描卡内）。

- 窗口默认 1280×820，最小 900×600（`tauri.conf.json`）；内容不得横向溢出。
- 内容区内边距 `20px 24px 24px`（`.page`），区块间距 16（`.page` 的 `gap`）。

### 5.2 顶部导航

`--bg-elevated` 底 + 底部 1px `--border`；标签 13px/500；未选中 `--muted`，hover 转 `--fg`；选中 `--accent` + 2px `--accent` 下划线。顺序固定：**扫描 → 发现 → 规则 → 历史 → 设置**（工作流顺序，不是字母序）。导航是 `role="navigation"` 的 tab 条，当前项需可被辅助技术识别。

### 5.3 页面结构

页面统一为「标题区 → 工具区 → 主体区」：

- **标题区**（`.page-head`）：`h2` 视图名（`--fg-strong`，18px）+ 副标题（`.page-sub`，`--muted`，12.5px，限宽 720px，一句话说明本页能做什么与边界）。
- **工具区**（`.toolbar`）：只放筛选、搜索、计数与视图内主操作；右侧计数用 tabular-nums。
- **主体区**：扫描页与设置页为卡片纵向流；发现页为左右两栏；规则页与历史页为表格。

### 5.4 五视图的视觉分工

| 视图 | 角色 | 视觉重心 |
|---|---|---|
| 扫描 | 输入与进度 | 大面积留白；进度条是页面唯一高饱和元素；工作区路径用等宽字体 |
| 发现 | 核对与处置 | 左右两栏：列表占剩余宽度，详情固定 `clamp(340px, 34%, 440px)`；列表 chip 密集，详情承载证据与代码 |
| 规则 | 资产治理 | 单栏宽阅读；规则 id / 语言 / 维度用等宽；编译错误用 `--error` 标注 |

### 6.3 组件规格

**顶部导航**：见 §5.2。

**按钮**
- primary：`--accent` 底 + `--fg-on-accent`（`#05101f`）文字 + 600 字重；hover 底色改 `--accent-2`（现状 `#7cb1ff` 是品牌外的第四个蓝，应收敛）。
- 次级按钮：`--surface-2` 底 + `--border-strong` 描边；hover 提亮到 `--surface-3`。
- ghost：无底，`--muted` 文字，hover 转 `--fg`。
- 危险按钮：仅删除类操作，文字用 `--error`，仍需二次确认。
- 尺寸：默认档 36px 高（`padding 7px 14px` + 13px 字号）；紧凑档 `.btn-sm` ≈ 29px（`padding 4px 10px` + 12px 字号），只用于表格操作列。
- 禁用：`opacity .45` + `cursor: not-allowed` + `disabled` 属性。

**输入与选择**：36px 高，`--surface` 底 + `--border-strong` 描边（承载信息，需 ≥ 3:1）；focus：描边转 `--accent` + `0 0 0 3px --accent-soft` 外扩光晕；placeholder 用 `--faint`；路径输入使用等宽字体。

**卡片**：`--surface` 底 + `--border` 描边 + 10px 圆角 + `16px 18px` 内边距；卡头（`.card-head`）标题 `--fg-strong` 14px、下间距 12px，右侧为操作区；卡片之间 16px 间距（`.page` 的 `gap`）。

**发现列表与详情**
- 左列表：每行 = 严重级 chip + 维度 badge + 路径（等宽 12px `--muted`）+ 规则 id + 消息摘要；选中行 `--accent-soft` 底 + 2px `--accent` 左侧内阴影。
- 右详情：消息（`--fg` 13px）→ 标签行（严重级 / 维度 / degraded）→ 代码证据块 → 捕获变量 → 污点链 → 相关段落。详情面板 `--surface` 底 + `--border` 描边 + `14px 16px` 内边距。
- 代码证据块（`.code-block`）：`--bg-elevated` 底 + `--border` 描边 + 6px 圆角 + `10px 12px` 内边距 + 等宽 12px；`white-space: pre-wrap` 并允许横向滚动。
- 表格形态（历史页 / 规则页）与列表形态共用同一套行高与 chip 规格；表格字号 12.5px。

**Chip / Badge**

| 元件 | 规格 |
|---|---|
| 严重级 chip（`.sev-chip`） | 语义色文字 + `rgba(色,.12)` 底 + `rgba(色,.30)` 边框 + 文案（错误 / 警告 / 提示） |
| 计数 chip（`.count-chip`） | 同色系但无边框，用于汇总条 |
| 维度 badge（`.dim-badge`） | `--surface-3` 底 + `--muted` 文字，中性，不编码严重性 |
| 状态 chip（`.status-chip`） | ok = `--info`；muted = `--muted` + `--border`（如「已配置 / 未配置」） |
| `degraded` 标记 | `--warning` 色 + `rgba(240,179,92,.10)` 底，明确标注解析降级 |
| 参考标签（`.discipline-tag`） | `--warning` 色 + 淡底 + 固定文案「非确定性参考 · 不参与门禁」，不得省略 |

chip 尺寸：严重级 chip `padding 1px 8px` + 11.5px/600 ≈ 20px 高；计数 chip `padding 4px 10px` + 12px ≈ 26px；维度 badge 与严重级 chip 同档、`--surface-3` 底。

**弹层（Modal）**
- 遮罩 `.modal-backdrop`：固定满屏、`--overlay-scrim`、`z-index: 50`、四周 24px 安全内边距。
- 壳体 `.modal`：宽 `min(640px, 100%)`、高 `min(640px, 88vh)`、`--surface` 底 + `--border-strong` 1px + 10px 圆角 + `16px 18px` 内边距 + 12px 内容间距 + `--shadow-overlay`。
- 结构：`modal-head`（标题 14/600 + 右侧关闭图标按钮）→ 主体 → `modal-foot`（左：当前路径等宽 11.5px；右：ghost 取消 + primary 确认）。
- 语义：`role="dialog"` + `aria-modal="true"` + `aria-label`（弹层标题）；关闭按钮带 `aria-label="关闭"`。
- 弹层是全应用唯一允许使用遮罩与阴影的层；不得用它承载与当前页无关的流程。

**进度与状态**：6px 高、999px 圆角，填充 `linear-gradient(90deg, var(--accent), var(--accent-2))`（呼应品牌镜圈渐变），轨道 `--surface-3`；不确定进度为 35% 宽滑块 1.2s 循环；百分比用 tabular-nums。**扫描进度是界面中唯一允许的持续动效。**

**空态 / 错误态**：空态居中标题 `--fg-strong` + 一句说明 `--muted`，不插画、不用感叹号；错误态 `--error` 文字 + 可读原因 + 可执行下一步，不用弹窗 alert，不闪烁。

**焦点态**：统一 2px `--accent` 描边 + 3px `--accent-soft` 外扩；键盘可达路径不得弱于鼠标（现状仅输入类控件实现，见 §11 第 11 项）。

## 7. 字体、间距与动效

### 7.1 字体

| 场景 | 字体栈 |
|---|---|
| UI | `Inter, -apple-system, "SF Pro Display", "PingFang SC", "Microsoft YaHei", sans-serif` |
| 代码 / 路径 / 规则 id / YAML | `"JetBrains Mono", ui-monospace, SFMono-Regular, Menlo, monospace` |

- 字号阶（实现取值）：11（辅助标签）/ 11.5（chip）/ 12（密排与代码）/ 12.5（副标题、表格）/ 13（控件与正文默认）/ 14（卡头、详情标题）/ 18（页面标题）/ 22（统计大数字）。行高：正文 1.55，密排（表格、列表）1.4。
- 11.5 与 12.5 是唯一允许的半档，只用于 chip 与密排说明文本；不得再引入其它小数档。
- 字重：400 正文、500 控件、600 强调与关键数字、650 仅字标使用。
- 数字（计数、百分比、行列号、字节数、时间戳）一律 `font-variant-numeric: tabular-nums`。
- 中英混排：中文与拉丁/数字之间留一个空格；中文标点用全角。
- 代码块、路径、规则 id 一律等宽；除语法高亮外不做着色，避免与严重级色冲突。

### 7.2 间距与圆角

几何 token（`apps/desktop/src/styles/global.css:19-21`，本次不调整）：

| token | 值 | 用途 |
|---|---|---|
| `--space` | `8px` | 控件间距、行内 gap |
| `--radius` | `10px` | 卡片、工具栏、表格容器、弹层壳体 |
| `--radius-sm` | `6px` | 输入框、按钮、代码块、统计格、目录项 |

- 8px 基网格；例外：4px（图标与文字间隙）、6px（表格操作列 gap）、12px（卡片内块间距）、2px（选中态内阴影）。
- 圆角档位：4px（`degraded` 等小标记）、6px（控件）、10px（卡片 / 弹层）、999px（chip 与滚动条）、0（导航标签，用下划线表达激活）。
- 控件高度：输入框 / 选择框 / 默认按钮 36px，紧凑按钮 `.btn-sm` ≈ 29px，chip 20–26px。
- **层级靠「表面阶梯 + 描边」而非阴影**。仅弹层允许遮罩与阴影：`--overlay-scrim` + `--shadow-overlay` + `--border-strong` 描边。
- 滚动条：宽 10px，滑块 `--surface-3`（hover 转 `--border-strong`），2px 透明描边留白，轨道透明。
- 表面相邻层对比低（1.1–1.4:1）是允许的，边界靠描边补齐；不要为了「更亮」而破坏与品牌底色的关系。

### 7.3 动效与交互

- 过渡 120–200ms，`ease`；只动 `transform` / `opacity` / `background` / `border-color`，不动布局尺寸。
- 唯一常驻动效是扫描进度；列表展开、详情切换用淡入（≤ 150ms）。
- 尊重 `prefers-reduced-motion: reduce`：关闭滑块动画与所有过渡，进度改为静态百分比（现状尚未实现，见 §11 第 12 项）。
- 键盘可达：Tab 顺序 = 视觉顺序；Esc 关闭浮层；扫描 → 筛选 → 查看详情全流程可不依赖鼠标。
- 破坏性操作（删除基线、删除扫描记录、覆盖规则）需二次确认，确认文案写明后果与影响范围。

## 8. 文案与语气

### 8.1 语气

- 界面语言简体中文；技术名词保留原文（LLM、Provider、SARIF、AST、tree-sitter、fingerprint、degraded）。
- 中文与拉丁/数字之间留一个空格；中文标点用全角。
- 短句优先：状态提示用「运行中 / 已停止 / 未配置 / 数据过期」这类短状态词，不用整句。
- 空态写法固定为「发生了什么 + 为什么 + 怎么做」。
- 危险操作必须写明对象、后果与是否可恢复。

### 8.2 措辞红线（Domain 约束在 UI 的落地）

界面文案与 Domain Spec 同样具有约束力，实现时按下列硬性规则：

- 规则消息只表述「出现了某种构造」，UI 不得出现「可利用」「可被攻破」「已证实漏洞」「攻击路径成立」。
- v1/v2 的近似能力必须带限定语：「不可信数据可能到达」（污点）、「启发式」（重复与复杂度度量）。
- LLM 产出统一带「非确定性参考 · 不参与门禁」标签，不得与发现混排在同一计数口径里。
- `degraded` 发现必须显示标记，且与正常发现同语义参与基线与门禁（Domain §3.2）。
- 「未发现问题」不等于「代码安全」，空态与提示文案照此写。
- 计数口径与报告一致：门禁只看新增（指纹相等性），不因 UI 折叠而改变数字。
- 严重级文案固定为「错误 / 警告 / 提示」，维度固定为「安全 / 业务逻辑 / 质量」，置信度固定为「高 / 中 / 低」（`labels.ts` 是唯一文案来源）。

### 8.3 敏感信息处理

- 密钥（LLM Provider API Key）只显示「已配置 / 未配置」，任何界面、日志、导出物都不得回显明文（Domain §3a.1）。
- 复制类操作（`CopyButton`）复制的内容必须是可公开的只读信息；安装令牌、Webhook、密钥等一律遮蔽（`••••`）。
- 扫描路径是本地工作区相对路径，不做脱敏改写，但不得写入报告之外的对外通道。

## 9. 无障碍与响应式

- 正文对比 ≥ 4.5:1，大字与非文本 UI ≥ 3:1；见 §3.4 实测表。
- 颜色不是唯一编码：严重级、维度、状态一律带文字；degraded 与参考层带专属文案。
- 焦点始终可见（§6.3 焦点态）；`:focus-visible` 与 `:focus` 同等对待，键盘可达路径不得弱于鼠标（全局规则的缺口见 §11 第 11 项）。
- 点击目标 ≥ 28×28：输入与默认按钮 36px，紧凑按钮 `.btn-sm` ≈ 29px，表格行内操作不得小于 28px。
- 尊重 `prefers-reduced-motion` 与系统缩放：窗口最小 900×600（`tauri.conf.json`），内容不得横向溢出；表格在窄窗口下允许横向滚动，不隐藏列。
- 界面语言简体中文；代码、路径、规则 id 保持原文，不翻译。

**已落地**：`role="alert"`（扫描失败、规则编译失败、LLM 错误、目录读取失败）、`role="status"`（扫描进度、保存与检查结果）、`aria-label`（主导航、规则表、复选框、路径输入、复制按钮、关闭按钮）、`aria-hidden`（纯装饰符号）、`role="dialog"` + `aria-modal`（目录选择器）。

**待补**（§11）：导航当前项的 `aria-current`、全局 `:focus-visible` 规则、`prefers-reduced-motion` 适配、弹层 Esc 关闭与焦点陷阱。新增区域必须沿用上述语义写法，不得只靠视觉表达状态。

## 10. 变更治理与视觉验收

**改稿流程**：改实现 → 回写本文对应章节 → 视觉验收 → 若行为变更则同步 `.specs/domain/`。

**新增视图 / 组件的最低要求**

1. 必须落在既有五视图内或作为既有视图的子区块，不新增顶层导航项。
2. 必须复用 §3.2 token 与 §6.3 组件几何，不写字面色值。
3. 必须补齐加载态、空态、错误态（§6.2）。
4. 必须登记在 §4 页面地图与 §6.1 组件清单中。
5. 涉及能力边界表述的，必须同时核对 §8.2 措辞红线。

**视觉验收口径**

- 以默认窗口 1280×820 对照扫描 / 发现 / 规则 / 历史 / 设置五视图；另以最小窗口 900×600 复查溢出与可点击性。
- 对照对象是**本文**，不是实现现状；实现与本文的差异应在 §11 有条目。
- 若执行环境没有可用浏览器或截图能力，必须把视觉验收标记为**未完成并说明阻塞**，不得以源码检查冒充截图验收。

**实现侧的硬约束**

- 色值、间距、圆角、字号一律取 token，不写字面量。
- 新增 token 必须先在 §3.2 登记，再在实现中消费。
- 改动影响 chip、状态标签、进度条规格时，必须回到 §6.3 重新对照，而不是各视图自由发挥。
- 颜色相关改动不影响 Domain 确定性约束（Domain §2）：颜色不进入 Finding / ScanEvent / 报告。

## 12. Do / Don't 速查

| Do | Don't |
|---|---|
| 用 `--accent` 标记当前焦点，用 `--accent-2` 做渐变终点 | 用品牌色铺大面积背景 |
| 严重级 = 颜色 + 文字 | 只用颜色区分严重级 |
| 维度用中性 chip | 给三个维度各配一个颜色 |
| 深色 UI 用描边分层 | 堆叠发光与霓虹阴影 |
| 空态写「未发现问题不代表安全」 | 空态写「一切安全」 |
| LLM 结果标「非确定性参考 · 不参与门禁」 | 把 LLM 建议并入发现计数 |
| 消息只说「出现了构造」 | 说「可利用 / 已证实漏洞」 |
| 破坏性操作二次确认并写明后果 | 直接删除历史与基线 |
| 密钥只显示「已配置 / 未配置」 | 回显密钥明文或掩码位数不足 |
