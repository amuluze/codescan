# 严重级与置信度校准

## severity（按影响，不按模式）

- `error`：直接可达的高影响问题——远程代码执行、SQL/命令注入到敏感数据、鉴权绕过、越权读写、硬编码生产密钥、可导致数据损坏的未授权写。
- `warning`：需要特定前置条件或影响中等——存储型 XSS、SSRF 到元数据、对象级越权、路径穿越、CSRF 作用于状态变更、业务不变量可被绕过。
- `info`：真实但不可直接利用的缺口——加固项、防御纵深缺失、错误信息过量、弱算法用于非安全场景。

高严重级必须有完整证据链：可控输入 + 到达 sink + 缺失控制。只有模式没有链路时最多 `warning`，且置信度不得为 `high`。

## confidence

- `high`：片段内能证明输入可控、sink 可达、无有效缓解；引用行号与符号一致。
- `medium`：证据较强但缺少一环（如上游校验未提供、路由未展示），或缓解存在但无法确认覆盖当前路径。
- `low`：仅模式匹配、依赖未提供的上下文，或属于加固建议。

## 一致性

- 同一根因只报一次；严重级取最高影响，不按出现次数叠加。
- 不得把“缺少防御层”升级为 `error`；不得把测试/示例代码计入生产风险。
- `detail` 中的影响必须与 severity 对齐；写不出影响时降级或删除。
