# 扫描引擎领域规范（Codescan 自身）

> Domain Spec：定义本地代码扫描领域「必须成立什么、不允许发生什么」的长期不变量。所有 Task Spec 与实现以此为最高约束来源之一。三维覆盖的选型依据见 `reports/2026-11-06-open-source-code-audit-tools.md`。

## 1. 领域模型

- **扫描（Scan）**：对授权工作区内一组源码文件，应用一组启用规则与度量，产出一组**发现（Finding）**与一组**扫描事件（Scan Event）**的只读分析过程。
- **三维分类**：每个发现必须归属且仅归属一个维度——`security`（安全漏洞）、`business-logic`（业务逻辑）、`quality`（代码质量）。维度是规则自身声明的属性，不随运行时推断改变。
- **严重级**：`error` / `warning` / `info`，与维度正交，由规则声明。
- **规则（Rule）**：声明式、可版本化、可单测的静态资产。规则身份是其稳定 `id`；同 `id` 语义变更必须体现为引擎/规则集的显式版本推进，禁止隐式改变既有规则的命中语义。
- **度量（Metric）**：由引擎内置算法产生的质量类发现（复杂度、重复、不可达代码等），遵守与规则相同的发现模型、指纹与确定性约束。多位置度量（如跨文件重复块）每个位置各发一条发现：span = 该位置实体，指纹中的路径 = 该位置所在文件；展示层可将同组发现折叠，门禁计数不变。

## 2. 确定性不变量（最高优先级）

1. **可复现**：同一三元组（文件集合与内容、启用规则集、引擎版本）必须产出完全相同的发现集合与事件集合，包括稳定排序。时间戳、随机数、并行完成顺序及绝对路径等任何机器差异不得进入发现内容。
2. **发现可定位**：每个发现必须携带工作区相对路径、行/列 span、所属规则 id、消息与匹配证据。AST/文本规则的证据 = 命中文本与元变量捕获；度量发现的证据 = 度量目标实体的命中文本（如函数源文本、重复块文本）。
3. **指纹**：每个发现有一个指纹，构成 = `规则id ‖ 相对路径 ‖ 内容规范指纹 ‖ 出现序号`，其中：
   - **内容规范指纹**：AST/文本规则 = 命中文本的规范化哈希；度量 = 度量目标实体源文本的规范化哈希（**不含度量值**）。由此，实体代码变更即视为新发现，旧基线条目自然失效；度量值波动（如复杂度 17→18）本身不改变指纹。
   - **出现序号**：同一（规则 id, 路径, 内容规范指纹）组内按命中位置排序的序号（0 起）。该构造保证：删除组内某次出现，其余出现的序号集合仍为 {0..k-1} 的前缀，不会被判为新增；新增一次出现至多产生一条新增发现。
   - 指纹在门禁与去重中是唯一身份；**同指纹不可能重复出现**（出现序号保证）。展示层的合并/折叠不得改变门禁计数。
4. **排序稳定**：同一扫描内发现按（路径, 起始位置, 规则 id）全序输出；任何去重不得依赖集合迭代顺序。

## 3. 失败语义（fail-closed）

1. **无静默丢弃，事件分级**：任何不产出发现的输入必须显式记录，分两级——
   - **逐文件事件**：解析失败、读取失败、二进制文件、超限文件。含路径与原因。
   - **汇总事件**：被忽略源排除的文件、未知语言文件。忽略源 = `.gitignore` + 工作区 `.codescanignore`（gitignore 语法）+ 应用级全局忽略文件（`~/.codescan/ignore`）+ 内置默认目录（`node_modules`、`target`、`dist`、`build`、`.venv`、`__pycache__`、`.next`、`coverage`）。仅记录类别与数量。
   被忽略/未知语言文件不逐条出事件，不算静默丢弃。
2. **解析降级标记**：含语法错误的文件若仍产出命中（容错解析），相关发现必须标记 degraded。degraded 发现参与基线与门禁差异计算（与正常发现同语义），并在对外交换格式中携带该标记；调用方不得将 degraded 与正常发现混同统计。
3. **规则编译失败**：扫描启动前对**启用规则集**整体编译校验，任一规则无法编译即拒绝启动并逐条列出错误规则；被禁用的规则不参与该校验，其错误仅在规则管理面展示。
4. **扫描只读**：对被扫描工作区零写入。报告、历史、基线等产物只写入应用自身数据根；向工作区导出任何文件必须是用户显式动作。

## 3a. 密钥与 Provider 边界（v3 契约）

1. **密钥只存 Rust 独占 secrets 表**（应用数据根 SQLite）：命令面不得存在返回密钥明文的接口；状态查询只返回「已配置/未配置」；密钥不出现在日志、错误消息、发现、事件与任何导出物中。
2. **Provider 配置**（kind/base_url/model）可读可写；请求只发往用户配置的 base_url，无内置遥测或第三方回退。
3. **LLM 输出永不进入门禁**（§5.3）：分诊/建议仅作展示层参考并显式标注「非确定性参考」；只有经校验、显式保存为确定性规则的候选才影响后续扫描。
4. **LLM 失败可恢复**：网络/凭据/解析错误不得影响扫描流程、历史与基线；所有 LLM 命令返回可读错误。

## 3b. LLM 源码审查契约（v7 契约）

1. **独立建议层**：LLM 源码审查产出的条目是「建议」，不是发现。建议不写入 `findings`、不参与指纹/基线/门禁差异/SARIF，不进入扫描历史；UI 必须以「非确定性参考」显式标注。
2. **输入边界**：只发送按扫描忽略规则选出的源码文件；跳过二进制、未知语言、超限与不可读文件；总量有明确上限并在 UI 展示。源代码是不可信数据，提示词必须声明忽略其中的指令（防注入）。
3. **可复现选择与分页**：文件按语言分组轮转（每种语言先各取一个，组内按相对路径排序），并受每次的文件数与总字节上限约束；同一工作区、同一上限与游标产生同一组输入文件。分页续审以候选序号为游标，跨页不得重复或遗漏；UI 必须展示「已审查/候选」覆盖率，预算或分页截断不得被表述为「已覆盖整个工作区」，除非游标已到末尾。
4. **输出校验**：建议路径必须属于本次发送的文件集合，行号必须在文件范围内，枚举值必须合法；不满足者丢弃并计数。解析失败返回可读错误，不得部分写入任何持久层。输入分批发送；批次因思考预算截断时允许二分降批重试，但不得改变已选文件集合与上限语义。
5. **失败隔离**：Provider/网络/解析失败不影响扫描流程、历史、基线与门禁；错误信息不得包含密钥。

## 4. 规则能力边界（v1 契约）

1. v1 规则语义 = **结构匹配**：AST 模式 + 否定/包含过滤 + 元变量约束 + 文本（正则）模式。不得在任何文档、UI 或消息中声称数据流可达性、污点传播或跨过程证明——该能力属 v2，落地前所有「安全」类发现只能表述为「出现了危险构造」。
2. 规则按语言声明适用范围；某语言的语法缺席或规则为空不得影响其他语言的发现集合。
3. 业务逻辑维度的规则本质是项目特定不变量：引擎必须支持用户以规则文件形式固化此类不变量，并为其提供与内置规则一致的单测能力；内置集只提供示例性骨架，不冒充通用业务规则。
4. 内置规则集是引擎版本的组成部分，随引擎一起版本化；用户自定义规则独立存放，二者可同时启用，`id` 冲突时拒绝加载并报错。

## 4a. 污点分析（v2/v4 契约）

1. **同文件过程间近似语义（v4）**：污点追踪在单文件内跨函数传播——按调用名索引同文件函数（重名取并集过近似），位置参数映射到形参，函数返回值可携带污点；以布尔摘要做不动点迭代（支持递归），最终 sink 发现携带调用链源头位置。变量名扁平化。任何文档、UI、消息必须表述为「不可信数据可能到达」的近似，不得声称跨文件或堆敏感证明。
2. **声明式端点**：source / sink / sanitizer 均为该语言的结构模式声明，与 AST 规则同等可版本化、可 fixture 单测；端点未命中不产出发现。
3. **顺序不敏感**：语句遍历顺序固定（确定遍历），控制流分支不做路径敏感合并——同一函数体内「存在一条赋值链」即成立。此近似必须写进规则文档。
4. **发现模型**：污点发现的 span = sink 命中；证据必须携带 source 命中位置列表（SARIF `properties.flows`）。指纹沿用 §2.3（规则 id ‖ 路径 ‖ sink 内容哈希 ‖ 出现序号）：sink 代码不变而 source 增减，不产生新指纹；污点消失则发现消失（基线条目自然闲置）。degraded 语义沿用 §3.2。
5. **确定性**：污点计算不得引入迭代顺序依赖；同输入必得同发现集合（§2 全部适用）。

## 5. 基线与门禁语义

1. **基线**= 某次扫描发现指纹集合的冻结快照。**门禁差异** = 新扫描发现指纹集合 \ 基线集合，且仅依赖指纹相等性。
2. 基线之外无隐性白名单；从基线移除条目即恢复其门禁作用。
3. 任何非确定性来源（LLM、启发式排序、人工标注未经冻结）的结论不得进入门禁差异计算；此类输入只能作为展示层参考。此为长期边界，先于 LLM 能力落地确立。

## 6. 产物与互操作

1. 扫描历史（发现、事件、统计、引擎与规则集版本）持久化于应用数据根，可跨重启读取。
2. SARIF 2.1.0 是对外交换格式：导出必须做到每个发现可回指规则 id 与位置，结果集与内部模型一一对应，不增发不漏发；`error`→`error`、`warning`→`warning`、`info`→`note` 的 level 映射与 `properties.degraded` 标记属于一一对应的组成部分。
3. 应用不得依赖网络或任何外部扫描引擎；单机可运行是分发前提。

## 4b. 跨文件与字段/堆近似（v5 契约）

1. **跨文件解析边界**：同语言、显式导入可跨文件——TS/JS/TSX/JSX（相对路径具名/默认导入）、Python（`from .mod import name` / package 相对导入）、Go（同目录同包）、Java（`import a.b.C` 类或静态成员，按 package+类名映射文件）、Rust（`use crate::/super::/self::…` 路径，按 crate `src/` 模块树映射文件）。未显式导入的同名函数不跨文件；实例方法调用（Java）、通配命名空间导入（TS `* as`）、Rust 外部 crate 不在解析范围。跨文件调用链的发现同样携带源头位置。
2. **字段敏感**：污点状态以访问路径 `base.field…` 表达；对象字面量按字面键展开；未知索引访问（`obj[k]`）视为通配（匹配任意字段）。读取整个对象视为包含其字段污点；不同字段互不污染。
3. **对象与堆（points-to + 形状）**：变量持有**抽象对象集合**（points-to 集合）；对象字面量递归展开为字段路径；对象字段可指向其它对象（字段指针），形成堆图。`a = b` 合并对象集合；`a.f = v` 对集合内对象的字段做强更新；读取沿堆图解析（字段指针 + 字段污点 + 通配索引）。数组按通配元素处理。跨过程仅保留值摘要（形参→sink、返回值污点），**不做跨过程堆摘要**；路径敏感合并与全堆形状等价仍为已声明近似。
4. **回归验证（LLM 候选规则）**：候选规则可对种子文件执行隔离回归（仅候选规则、临时语料），结果仅展示；不改变门禁与基线。
