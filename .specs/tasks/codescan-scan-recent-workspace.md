# Task Spec：扫描页工作区的历史快捷选择

task-id: `codescan-scan-recent-workspace`

## 背景与目标

现状：扫描页选择工作区只有「选择工作区」目录浏览器一条路径；应用每次启动 `workspace` 归零，重扫同一目录必须重新打开弹层逐级导航。扫描历史（SQLite）已记录每个扫过的 root 与时间戳，扫描页却没有利用。

目标：扫描页提供基于扫描历史的工作区快捷选择——一次点击直达最近扫过的目录；不改变扫描、历史与门禁语义。

## 范围与验收

1. **数据来源**：复用 `list_scans`（不改后端）；按 root 去重、以最近扫描时间倒序，最多 8 条。
2. **交互**：工作区路径行内「选择工作区」旁渲染原生下拉（`aria-label="从历史选择工作区"`，占位「历史工作区…」）；选中即写入 `workspace`，随后「开始扫描」用该 root。无历史时不渲染下拉。
3. **刷新时机**：ScanView 挂载时加载一次；`scan://finished` 后再拉一次，使刚扫过的工作区排到最前。
4. **失败语义**：`list_scans` 失败静默（快捷选择是可选便利，不产生错误横幅）；所选目录若已不存在，由既有扫描失败路径给出可读错误（fail-closed，不预先校验存在性）。
5. **空态文案**：有历史时提示「从历史快速选择，或点击「选择工作区」浏览本地目录。」；无历史保持原文案——引导只提及实际可用的入口。

## 排除项

- 不持久化「上次工作区」（跨重启记忆由历史快捷选择覆盖）。
- 不在 DirectoryPicker 弹层内嵌历史列表；不做路径存在性预校验命令。

## 关联

- 复用：`platform.ts` 的 `api.listScans`；`scanStore` 扩展 `recentRoots` / `loadRecentRoots`。
- Domain：不涉及扫描引擎不变量；仅扫描页展示层。
- DESIGN：§4 页面地图扫描行与 §4.2 空态文案口径已同步。
