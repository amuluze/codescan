# Task Spec：Codescan v1 —— 本地代码扫描桌面应用

task-id: `codescan-desktop-v1`

## 背景与已定决策

`reports/2026-11-06-open-source-code-audit-tools.md` 的结论：三维（安全/业务逻辑/质量）审计只能由「确定性规则 + 项目自定义不变量」达成，LLM 产出不得进门禁。用户已拍板四个方向性决策：

1. **产品形态**：Tauri 2 + React 19 桌面应用（复刻 axiom 技术栈：TypeScript、Vite、Zustand、Rust 侧 SQLite）。
2. **引擎策略**：自研 AST 规则引擎（tree-sitter 语法族），不编排外部引擎。已知并接受：这是重造规则库的路线，换取零外部依赖、单二进制分发与规则语言完全可控。
3. **语言范围**：v1 一次铺开 6 个语法族——TypeScript/TSX、JavaScript/JSX、Python、Java、Go、Rust。
4. **安全深度**：v1 = 结构模式规则 + 质量度量（Domain Spec §4），过程内污点追踪为 v2 路线；LLM 辅助层二期，v1 纯确定性。

规则模式语言采用 tree-sitter query 语法 + 过滤器（`not`/`inside`）+ 元变量正则约束，不发明独立 DSL；由此规则作者需掌握对应语法的 query 语法，此代价记入规则编写文档。

## 范围

### 引擎（Rust，可完全无头测试）

- 语法接入：tree-sitter 各语言 grammar；文件按扩展名识别语言；遵循工作区 `.gitignore`（忽略与未知语言文件按 Domain §3.1 汇总事件记录）。
- **文件上限**：单文件 1 MiB（引擎常量，文档冻结），超限逐文件事件并跳过。
- 规则模型：YAML 规则；枚举冻结——dimension ∈ {`security`, `business-logic`, `quality`}，severity ∈ {`error`, `warning`, `info`}，language ∈ {`typescript`, `tsx`, `javascript`, `jsx`, `python`, `java`, `go`, `rust`, `*`}；字段：id、language、dimension、severity、message、AST query 模式、`not`/`inside` 过滤器、元变量正则约束、文本正则模式（`*` 语言）。规则编译期为静态校验（query 语法、捕获名、语言匹配），校验范围 = 启用集（Domain §3.3）。
- 度量（quality 维度，引擎内置，走统一发现管线与指纹规则 Domain §2.3）：函数圈复杂度、函数长度、最大嵌套深度、重复代码块（跨文件，规范化行序列）、终止语句后不可达代码。跨文件未引用分析不在 v1。
- 发现/事件模型、指纹、稳定排序：按 Domain Spec §2。
- SARIF 2.1.0 导出：与内部发现一一对应（含 level 映射与 `properties.degraded`，Domain §6.2）。
- 基线：快照创建、差异计算（仅指纹相等性）。
- 取消：取消后部分结果整体作废（不产出报告、不写历史），扫描以被取消状态结束。

### 桌面应用

- 工作区选择（只读扫描，按 Domain Spec §3.4 零写入）。
- 扫描执行与进度（文件数、阶段），可取消。
- 发现浏览：按维度/严重级/语言/规则过滤，定位到文件:行，展示命中文本与元变量捕获，degraded 标记可见。
- 规则管理：内置规则列表与启停（禁用规则的编译错误仅在此面展示）；自定义规则目录加载、YAML 校验错误展示；规则详情。
- 扫描历史（SQLite，Rust 侧独占读写）：跨重启可读；任意历史扫描可设为基线、可导出 SARIF。
- 门禁差异视图：相对当前基线的新增发现。

### 内置规则集（随引擎版本化）

- 通用文本规则 ≥6 条（如密钥模式、TODO/FIXME 债务）。
- 每个语法族 AST 规则 ≥6 条（安全向危险构造 + 质量向），消息只表述「出现构造」，不声称可利用性。
- 业务逻辑维度：提供 ≥2 条示例骨架规则（标注为示例）证明自定义不变量通道可用。

### 规则 fixture 格式（A2 的判定基础）

- 位置：`rules/tests/<rule-id>/` 下按扩展名识别语言；同一 fixture 文件可服务多条规则。
- 标注：期望命中行**紧邻上一行**的行注释——`// ruleid: <id>`（TS/TSX/JS/JSX/Java/Go/Rust）或 `# ruleid: <id>`（Python）；同文件多规则用多行堆叠标注。
- 判定：runner 对每个 fixture 文件运行**全部同语言启用规则**；期望集合 = 标注的 (规则 id, 文件, 起始行) 全集；实际集合 = 全部发现的 (规则 id, 文件, 起始行) 全集；**两集合精确相等**才通过（未标注的命中 = 过度匹配，失败；标注了未命中 = 漏报，失败）。

## 验收标准（全部可客观判定）

- **A1 确定性**：同一 fixture corpus 连续两次扫描的发现 JSON 与事件 JSON 字节相同（自动化测试）。
- **A2 规则单测**：每条内置规则至少被一个 fixture 标注覆盖（存在 `ruleid:` 期望且实际命中），按上述 fixture 格式判定；任一文件两集合不等即套件失败（自动化）。
- **A3 fail-closed**：含语法错误、二进制、未知扩展名、超限（>1 MiB）文件的 corpus：发现中不含它们；逐文件事件（解析失败/二进制/超限）与汇总事件（未知语言）分别按类别出现且可数（自动化）。
- **A4 指纹与基线**：① 纯行号漂移下指纹不变；② 同文件同规则同内容多重命中：删除其中一次出现后其余不产生新增发现、新增一次出现至多一条新增；③ 度量实体代码变更 → 指纹变化、门禁判新增，度量值单独波动 → 指纹不变；④ 基线差异精确等于集合差，移除基线条目后恢复门禁（自动化单测）。
- **A5 SARIF**：导出含 SARIF 2.1.0 必需字段（version、runs、results[].ruleId/locations/level），level 映射 error→error / warning→warning / info→note，`properties.degraded` 存在，结果条数与内部发现一一对应（结构断言测试）。
- **A6 度量正确性**：圈复杂度、函数长度（行数）、最大嵌套深度在已知答案 fixture 上逐一断言；植入的重复块被检出且 span 正确；终止语句后代码被标记不可达（自动化）。
- **A7 语言矩阵**：6 个语法族各有 fixture 且各 ≥1 条 AST 规则命中（自动化）。
- **A8 应用面**：vitest 组件测试覆盖「选择工作区→触发扫描→进度→发现列表过滤→详情」主链路；Rust 命令层集成测试覆盖 scan 命令返回、SQLite 持久化跨连接可读、基线设置与差异查询。
- **A9 性能**：≥1000 文件合成语料全量扫描 wall time ≤ 90s（debug 构建、Apple Silicon、自动化测试硬上限）；release 构建同语料以 60s 为参考目标人工记录实测值。
- **A10 可启动**：`npm run tauri dev` 启动无 panic、主窗口渲染（人工验收，记录步骤与结果）。
- **A11 取消语义**：取消后历史无新扫描记录、进行中部分结果不可见（Rust 命令层自动化测试）。

## 排除项

- 污点/数据流/跨过程分析（v2）；LLM 辅助层（二期）；CI/SARIF 上传集成；自动修复；跨文件未引用死代码检测；规则市场/远程规则源；Windows/Linux 打包（v1 只验证 macOS dev 形态，打包链路后置）。

## 失败语义补充（Task 级）

- 自定义规则 `id` 与内置冲突：拒绝加载该目录并逐条报错（对应 Domain Spec §4.4）。
- 空工作区/无匹配语言文件：扫描正常完成，发现为空，事件记录跳过统计。
- 取消扫描：按「范围-引擎」取消条目执行；验收见 A11。
