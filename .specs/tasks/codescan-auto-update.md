# Task Spec：应用更新的定期检查与顶栏升级提示

task-id: `codescan-auto-update`

## 背景与目标

现状：应用更新只能在设置页手动点「检查更新」。用户不主动点，就永远不知道有新版。

目标：应用在启动时与固定间隔自动检查更新；发现新版本后在顶栏版本号前给出升级提示图标，点击直达设置页完成更新。检查失败（开发模式未注册 updater 插件、端点不可达）不得打扰用户。

## 范围与验收

1. **定期检查**：`useUpdateCheck` 在应用挂载时静默检查一次，之后每 6 小时复查；定时器随组件卸载清理。
2. **共享事实**：`updateStore` 承载 `available`（发现的新版本）、`checking` / `installing`、提示与错误；设置页手动检查与后台检查共用同一份状态与同一次在途请求（并发检查合并为一次端点请求）。
3. **顶栏提示**：`App.tsx` 导航右侧版本号组内，升级图标渲染在版本号**之前**；仅在存在新版本时出现；图标带 `aria-label`（含新版本号）与 tooltip。
4. **跳转安装**：点击图标切到设置页「应用更新」卡，该卡展示新版本号与「下载并安装 vX」按钮（安装沿用既有 updater 流程：minisign 校验 → 替换 → 重启）。
5. **失败语义**：后台检查失败静默（无提示图标、无错误提示）；设置页手动检查失败仍以 `role="alert"` 展示可读错误，不阻断页面。

## 排除项

- 不做后台静默下载/自动安装——更新安装必须由用户在设置页显式触发。
- 不做版本号与最新发布版本的常驻并列展示（顶栏版本号恒为当前构建版本）。
- 不引入新的持久化（不记 last-check 时间戳、不写 SQLite）。

## 关联

- 复用既有 updater 链路：`platform.ts` 的 `updater.check` / `updater.installAndRelaunch`（端点为 GitHub Releases 的 `latest.json`，工件经 minisign 签名校验）。
- Domain：不涉及扫描引擎不变量；仅展示层。
- DESIGN：顶栏版本号组与 `.app-meta` / `.update-badge` 样式、组件清单已同步。
