# Task Spec：审查请求重试与失败页部分结果保留

task-id: `llm-review-retry-partial`

## 目标

LLM 源码审查遇到 Provider 过载（429 / 5xx / 529）时自动重试 5 次；重试耗尽后，保留当前页已完成批次的建议与复核结论，并按已完成文件推进游标，用户可继续审查剩余文件，而不是丢掉整页。

## 现状（证据）

- `review()` 对非 2xx 直接返回错误；529 显示为 `<unknown status code>`。
- `review_batched` 只对 thinking 截断做二分重试，其他错误立即 `return Err`。
- 当前页内已完成的批次存在局部 `Vec`，命令返回 `Err` 时全部丢失；前端只保留此前整页结果。
- 命令以 `selection.next_offset` 作为下一页游标，无法表达“页内部分完成”。

## 范围

1. **自动重试**
   - 仅对 HTTP 429、500–599（含 529）重试；首次失败后最多再试 5 次。
   - 指数退避（1s/2s/4s/8s/16s，单次上限 30s），尊重 `Retry-After`（按秒解析并封顶 30s）。
   - 猎取与独立复核都使用该策略；其他 4xx、解析失败、网络错误不重试。
   - 测试下退避为 0，避免等待。
2. **部分结果**
   - `review_batched` 返回结构化结果：建议、丢弃、复核过滤、已完成文件数/字节数、可选错误；遇到不可恢复错误即停止后续批次并保留已完成部分。
   - 命令在失败时返回 `ReviewResult.error`，`next_offset = page_offset + 已完成文件数`，`files_reviewed` 只计已完成文件。
   - 前端保留部分结果、设置错误并停止自动续审；「继续审查」从新游标继续，不重复已完成文件。
3. **契约**
   - Domain §3b 升版：过载重试、部分完成游标与错误字段；失败不得被表述为已覆盖全部候选。
4. **测试与文档**
   - Rust：状态码分类/退避/RRetry-After；529 两次后成功；6 次 529 后失败；两批中第二批失败时保留第一批并返回 `reviewed_files`/error；命令游标推进 helper。
   - 前端：部分结果保留、错误展示、继续审查携带新游标、文件计数不重复。
   - 文档：Domain、docs/llm.md、docs/en/llm.md、CHANGELOG。

## 验收标准

- [ ] 429/500/503/529 触发重试，最多 6 次总请求（1 次 + 5 次重试）；400/401 不重试。
- [ ] `Retry-After: N` 被采用且封顶 30s；无该头时指数退避。
- [ ] 529 连续两次后成功时审查返回建议，请求次数为 3。
- [ ] 连续 6 次 529 返回可读错误，且错误包含最终状态与响应摘要。
- [ ] 两批审查中第二批失败：结果保留第一批建议，`reviewed_files` 等于第一批文件数，`error` 非空，`next_offset` 为页起点 + 已完成文件数。
- [ ] 前端收到部分结果后不丢弃建议、显示错误、停止自动续审；点击「继续审查」使用新游标。
- [ ] `task check` 全量通过。

## 排除项

- 不对 4xx（除 429）、解析错误或网络错误自动重试。
- 不改变单页文件选择、字节上限、thinking 截断二分与复核降级语义。
- 不做跨页并发或请求取消。
