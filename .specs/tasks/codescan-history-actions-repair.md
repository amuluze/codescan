# Task Spec：历史页查看、基线与门禁差异修复

task-id: `codescan-history-actions-repair`

## 目标

修复历史页「查看 / 设为基线 / 门禁差异」的空态缺失、异步串数据、错误不可见和旧差异残留，同时补齐基线写入原子性与历史规则包完整性展示。保持 Domain §5 的指纹快照与集合差语义不变。

## 现状与失败证据

以下为 2026-11-28 静态调用链核查结果，尚未在真实 Tauri 页面运行复现；实现前先用 RED 测试锁定行为，竞态结论以逆序完成测试验证。

1. **无基线空操作（静态确定）**：`Store::gate_new()` 在无基线时返回 `None`，前端保存为 `gateNew=null`，`HistoryView` 不渲染差异区，点击「门禁差异」没有任何可见结果。
2. **结果归属缺失（静态确定）**：`gateNew` 只保存发现数组，不保存扫描 id，差异标题也不显示扫描 id；直接对非当前打开扫描计算差异时，页面无法辨认结果来源。
3. **异步覆盖（代码路径推导，待 RED 验证）**：`openScan()` 与 `refreshGate()` 都直接提交最后一次 resolved 结果，没有请求版本；逆序完成可让旧请求覆盖新选择。
4. **错误不可见（静态确定）**：三个行操作均以 `void action()` 丢弃 Promise，页面 `error` 只覆盖初始加载、删除和导出；事件与规则集读取失败被静默替换为空数组/`null`。
5. **旧差异残留（静态确定）**：`setBaseline()` 只更新基线信息；`deleteScan()` 仅在删除当前打开扫描时清理差异，基线或差异来源变化后仍可能展示旧结果。
6. **非原子基线切换（静态确定）**：`Store::set_baseline()` 分两次 SQL 插入基线、切换活动指针，未使用已有事务 helper。
7. **规格展示缺口（静态确定）**：`rule-pack-v1` 要求历史页展示规则包 id/version/integrity，当前只显示 id@version。

## 范围

1. **差异结果可辨认**：门禁差异区显示目标扫描 id，并区分加载中、未设置基线、无新增发现和有新增发现。
2. **最后意图生效**：快速连续查看或计算差异时，旧请求不得覆盖新请求；排序键是用户动作序列，不是请求实际发起时刻。查看完成后的自动差异继承该查看动作的意图序号，不得覆盖更晚的查看或显式差异。
3. **错误可见**：查看、设为基线、门禁差异失败均在历史页显示可读错误；发现读取成功但事件或规则集读取失败时保留发现列表，并明确标记元数据不可用。
4. **结果失效**：基线写入成功或任意历史删除成功后，作废旧差异及在途差异请求；即使后续信息刷新失败，也不得恢复旧结果。基线写入失败则保留原差异。删除基线来源扫描后不得继续显示旧基线；删除无关记录也统一失效差异，避免额外追踪来源。
5. **基线原子写入**：基线快照插入与活动基线切换在同一 SQLite 事务中，任一步失败均不新增快照、不改变活动基线。
6. **历史元数据补齐**：查看面板展示规则包 id/version/integrity；integrity 缺字段或为空串时显示未记录。旧历史缺少规则集快照字段时显示未记录，只有明确记录空数组时才显示 0 条/0 个。
7. **回归证据**：补充前端交互、逆序完成、失败与失效测试，以及 SQLite 故障注入测试；完成真实历史页走查并同步 DESIGN/CHANGELOG。

## 验收标准

- [x] **AC1 空态**：无基线时点击任一扫描的「门禁差异」，页面显示该扫描 id 和「未设置基线」提示，不再无反馈。
- [x] **AC2 结果归属**：加载、无基线、无新增和有新增四种差异状态均显示目标扫描 id；有新增时仍逐条显示路径、行号和规则 id。
- [x] **AC3 查看竞态**：两条扫描的查看请求逆序完成后，只展示最后选择扫描的发现、事件和规则集；旧响应不覆盖新状态。
- [x] **AC4 差异竞态**：以用户动作而非自动请求发起时刻排序；两条显式差异或连续查看产生的自动差异逆序完成后，只展示最后请求/查看扫描的结果，旧自动差异不得覆盖更晚的查看或显式差异。
- [x] **AC5 失败语义**：最新查看、基线写入、门禁差异 IPC reject 时出现 `role=alert` 错误，过期请求不得弹出旧错误；事件或规则集单独失败时发现仍可见，同时显示对应元数据不可用警告。
- [x] **AC6 基线与删除失效**：基线写入失败时原差异保持；写入成功时旧差异立即失效，即使后续基线信息刷新失败也不得恢复，并明确提示“基线已切换但信息刷新失败”。删除基线来源、差异目标或无关扫描成功后均统一失效旧差异；基线来源删除后不得继续显示旧基线。此前在途差异随后完成不得恢复旧结果。
- [x] **AC7 原子性**：故障注入使活动基线切换失败时，`set_baseline` 返回错误，基线表行数和原活动基线均保持不变。
- [x] **AC8 规则集与规则包信息**：有 integrity 的历史显示 id/version/integrity；字段缺失或为空串时明确显示未记录，不伪造值或保留空白哈希位。`ruleset={}` 等未记录快照不得显示为启用 0 条、规则包 0 个；只有明确记录 `enabled_rules=[]` / `packs=[]` 时才显示相应 0 数量。
- [x] **AC9 回归与实面**：相关 Vitest、`codescan-desktop` 无头测试、TypeScript 检查通过；真实历史页完成空态、正常切换、基线变更和规则包信息走查。精确逆序与 IPC 故障以可控自动化测试为证据，不宣称实面复现。

## 排除项

- 不修改指纹、基线集合差、degraded 或 LLM 不进门禁的 Domain 语义。
- 不新增桌面端门禁通过/失败策略或修改 CLI 退出码。
- 不做历史分页、超过 200 条记录的访问改造、基线条目编辑或基线删除界面。
- 不改变 SARIF 导出与历史删除确认流程。

## 回归风险

- 请求版本管理可能误丢弃最后一次有效响应，需覆盖同扫描重复点击和查看/显式差异交错。
- 差异失效策略可能误清除最后用户意图，需覆盖基线写入失败时保留原结果、成功时才失效。
- 元数据部分失败不得阻断发现查看，也不得伪装为空数据。
- SQLite 事务需复用现有 `Store::transaction()`，不得引入第二套写路径。
